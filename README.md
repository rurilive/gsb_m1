# votehal

纯标准库的众数与多数投票统计工具雏形，无外部依赖。

## 现状

votehal/naive.py 提供这些朴素能力：

- naive_counts、VoteTools.counts：对每个不同元素把整条序列从头再扫一遍数出现次数
- majority_value、majority_count、has_majority：对每个候选重扫得到次数，再逐个与阈值比较
- frequent_values：枚举全部候选，对每个候选重扫数次数，筛掉不达标的
- top_frequent：先反复重扫得到频次，再对全部元素做一次全排序
- two_pass_majority：一趟哈希统计频次加一趟按原序确认的两遍做法
- VoteTools：绑定一条序列，累计完整重扫次数与逐元素比较次数，可读取与清零

所有结果都对，但求多数元素要对每个候选重扫一遍，求众数要枚举全部候选
逐个重扫，前几频繁元素靠全排序，规模一大就慢。

## 问题

序列一长，完整重扫的次数就随不同元素个数成倍上涨，两两比较是平方量级；
同一批数据的频次被反复重新统计，没有一趟得出候选再验证的投票路，也
没有一趟统计频次再筛选的哈希路，想问多路互相印证也缺独立入口。

## 目标

在当前基础上补出摩尔投票法、哈希计数与推广投票法三条独立做法并互相
印证，暴露朴素重扫与投票、哈希访问次数的规模对照，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 投票路与哈希路对同一批数据的结果逐项一致，并与朴素重扫一致
