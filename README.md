# bittrix

纯标准库的整数位操作工具雏形，无外部依赖。

## 现状

bittrix/naive.py 提供几条朴素能力：

- popcount_str、popcount_loop：求二进制里一的个数，分别转成二进制串逐字符数一，
  以及反复右移并判最低位
- lowest_set_bit、highest_set_bit：求最低位一与最高位一的位置，靠逐位右移
- is_power_of_two：判断是否二的幂，靠数一的个数是否等于一
- reverse_bits：按定位宽做二进制逆序，靠位串切片翻转再转回整数
- common_prefix_length：两数在定位宽下二进制公共前缀长度，靠逐字符比对位串
- has_adjacent_alternating、all_adjacent_pairs_differ：二进制表示里相邻位是否
  互不相同，靠逐位比对
- gray_adjacent_one_bit：是否与相邻整数恰好相差一个位，靠位串逐字符比对
- bit_position_counts：对一个整数集合批量求每位置位计数，靠逐数逐位累加
- BitTools：绑定一个位宽，方法同上并累计访问位的次数，可读取与清零

所有结果都对，但每一项都要逐位循环或在位串上逐字符比对，位数一多、数一多，
循环次数就随位宽线性上涨，批量求每位置位计数更是双重循环，也没有逐步清除最低
位一、补码与运算、与自身减一相与、位扩散、分组位交换、异或求最高位这类位技巧
做法。

## 问题

位宽一变大，逐位右移的循环次数就跟着涨；求是否为二的幂、相邻位判定都靠把整数
转成二进制串再逐字符扫一遍，前面的位信息一点没被复用；批量求每位置位计数要用
双重循环，条数一多就更慢；想在位技巧做法与朴素做法之间互相印证也缺入口。

## 目标

在当前基础上补出位技巧路径与独立朴素路，两者对同一批数据逐项一致，并接上相邻
位差一位判定与批量每位置位计数，暴露两类计数的规模对照，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 位技巧路与独立朴素路结果逐项一致，两条路不许互相调用
