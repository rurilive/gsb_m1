# topichub

纯标准库的内存主题订阅代理雏形，无外部依赖。

## 现状

topichub/hub.py 提供最简单的主题订阅代理 TopicHub：

- subscribe、unsubscribe：按主题登记或注销一个回调，退订返回是否成功
- publish：按主题把登记过的回调挨个直接调用，返回全库单调递增的序号
- 每条 Message 带 topic、payload 与序号 seq，seq 跨主题共用
- 回调抛出的异常被吞掉并记入 errors，不影响其它回调
- pending：当前未确认的在途消息条数，朴素实现里恒为 0

## 问题

投递是即发即忘的：回调一返回就算送达，回调中途抛异常、消费者处理到一半
挂掉，这条消息就永久丢了，没有确认也没有重投，没有重投队列，没有死信，
没有注入时钟。主题只能精确匹配，订阅不了通配主题；订阅者无法说自己只想
要哪些消息，谓词过滤不存在；订阅者也没有缓冲上限的概念，慢订阅者只能看
着内存涨；退订之后那些还没处理完的在途消息该怎么处置，没有明确口径。

## 目标

在当前基础上补出多主题发布订阅与通配、订阅谓词过滤、至少一次投递与确认、
未确认重投与死信、顺序保证、背压与退订，见任务描述。约束：

- 现有行为与 tests/test_pubsub.py 基线保持一致（基线一个字不改）
- 纯标准库
- 重投与超时基于注入时钟，测试不依赖真实时间
