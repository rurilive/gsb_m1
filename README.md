# hldx

内存里的朴素有根树路径与子树统计，纯标准库，无外部依赖。

## 现状

`hldx/tree.py` 提供 `PathTree`，用父子边建一棵有根树（根 id 加
`(parent, child)` 边序列，边可以乱序）：

- `depth(u)`：顺着父指针一层层上爬数出深度
- `lca(u, v)`：两边各自逐层上爬，对齐深度后一起爬到重合
- `path_nodes(u, v)`：把路径上的节点逐个收进列表
- `path_sum(u, v)`：沿路径把节点权值一个个加起来
- `path_max(u, v)`：沿路径逐个节点取最大值
- `subtree_sum(u)`：从 u 出发把子树里每个节点都访问一遍再加
- `update(u, v, delta)`：把路径上每个节点权值逐个加上增量
- `add_subtree(u, delta)`：把子树里每个节点权值逐个加上增量
- `weight(u)` / `set_weight(u, value)`：权值读写，未设置的节点按 0 计

## 问题

每次路径与子树操作都要逐节点走一遍，链一长就退化成线性：`depth` 与
`lca` 顺着父指针一层层爬，`path_sum`、`path_max` 与 `subtree_sum` 逐个
节点累加，`update` 与 `add_subtree` 也是逐个节点改写。整树更新、长链上
的反复查询都顶不住，也没有任何计数能说明一条更聪明的做法省了多少。

## 目标

在当前基础上，以重链剖分为核心把 `PathTree` 扩成对数级的树链统计工具，
补出重链剖分本体、跳链的路径查询与更新、子树区间查询与更新、跳链求最近
公共祖先、链分解信息、复杂度计数与边界处理，见任务描述。约束：

- 现有行为与 `tests/test_tree.py` 基线保持一致（基线一个字不改）
- 纯标准库，不得引入任何外部依赖
- 逐节点那套路径保留，两条路对同一批数据给出的事实必须一致

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests
```
