# effecteval

一个纯标准库的算术表达式求值器，无外部依赖。规则引擎与电子表格里经常要让
用户写一小段表达式，再由程序算出一个数，effecteval 就是干这件事的那一层。

## 现状

- `effecteval/tokens.py`：`Token(kind, text, value, start, end)`，只记 src 上的
  字符下标区间，尚未把下标换算成行列号。
- `effecteval/lexer.py`：`tokenize(src)` 把原文切成 token，运算符最长匹配优先，
  `OPERATORS` 里含 `**`、`==`、`<=`、`&&` 等尚未接入语法的多字符运算符。
- `effecteval/parser.py`：`parse(src)` 是递归下降解析器，只覆盖加减、乘除取模、
  一元正负与括号，末尾残留 token（如 `1 2`、`1 == 2`）一律报错。
- `effecteval/eval.py`：`eval(src, env=None)` 每次调用都重新分词、重新解析再求值，
  语法树不缓存，相同表达式重复求值每次都从头再编一遍。
- `effecteval/errors.py`：`ParseError` 与 `EvalRuntimeError` 带出错表达式与字符
  下标，便于把报错定位回原文。

求值时变量从一个普通字典里查，查不到就算未定义变量报错。整个求值过程没有记忆化，
同一个子表达式被引用多次就重算多次；也没有任何可观测的副作用，没有上下文对象，
所有状态都留在一次函数调用之内。

## 问题

子表达式算过一遍就丢，大表达式里同一段被引用多次会反复重算；变量改了值之后
没有任何办法知道哪些结果还算得数、哪些已经作废；求值过程中想触发一点外部效果
（计数、打点）没有地方可放，更谈不上把这些效果记下来按原样重放一遍；逻辑运算
一旦接入，右侧分支不做短路就会算出多余的值、触发多余的副作用；一次求值走到一半
出错时，前面已经发生的效果没法收回；多个求值同时进行时也没有互相隔离的边界。

## 实现说明

依赖跟踪靠求值上下文里一张变量名到版本号的表：求值每个节点时把用到的变量记进
该节点的依赖集合，变量值一变，它的版本号就前进一格，旧结果据此判定失效。纯子
表达式按表达式原文加变量版本快照做记忆化，快照相同的复用缓存，快照变了自然换键
重算，没碰到的变量不动缓存。副作用不再直接作用于外部，而是写进上下文自带的
effect 日志，日志按发生次序记类别与参数，重放时照日志念一遍即可，同一个上下文
对象发出的效果不会流到另一个上下文里去。
