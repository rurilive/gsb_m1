# chainkit

一个纯标准库的矩阵链工具：持有一串矩阵的维度，求把它按结合律相乘的最少与最多
标量乘法次数、对应的加括号方案、最少次数的方案个数，以及同构的多边形三角剖分
最低代价。

## 现状

`chainkit/chain.py` 里全是朴素递归。最少次数与最多次数都对每个区间枚举全部断开
位置，左右两半各自递归重算代价，取最小或最大者；方案也靠同一套枚举回代拼出，
并列时取断开位置最小的那个；方案个数对每个断开位置重算两侧代价再相乘累加。
多边形三角剖分固定首尾边枚举中间顶点，左右各自递归重算。括号串与方案之间的
互转、以及从括号串重扫叶子端点算乘法次数，同样是直白写法。结果都正确。

## 问题

不同断开位置会产生大量相同的子区间，朴素写法每次都从头递归重算，同一段区间被
反复算上许多遍。矩阵一多，重复子问题的量级按指数上涨，明明只与区间端点有关的
代价却算不出缓存，链稍长就慢得不可接受；最多次数、方案个数、三角剖分各写各的，
彼此之间也没有任何可以对照的独立路径。

## 目标

把核心代价从递归枚举扩成以区间长度递增的二维动态规划：先按区间长度从小到大填满
最少乘法次数的表，再按写死的并列取法回溯出加括号方案；另起一条独立的枚举全部
加括号口径做小规模交叉核对，新老两条对同一批固定输入逐项一致。再补上最大乘法
次数与对应括号、多边形三角剖分最低代价、以及方案与显式括号字符串互转的确定性。
基线那条朴素路径保留，两条路给出的事实要对得上。详见任务描述。
