# ringbuf

多生产者/多消费者定长环形缓冲，网关进程内嵌使用，纯标准库（threading.Lock）。

## 语义

- `put(item)`：写入一个元素，永不阻塞；缓冲满时覆盖最老元素，count 不会超过容量
- `get()`：取出最老元素；缓冲为空时抛 `ringbuf.Empty`；每条消息只会被一个消费者取到
- `count()`：当前元素个数，取值范围 [0, capacity]
- `snapshot()`：按逻辑顺序（写入顺序）导出当前内容的副本，不影响缓冲状态
- 所有操作线程安全，可在多线程读写场景下直接使用

## 运行

```bash
python3 demo.py
```

## Known Issues

以下问题已修复（防回归测试见 `tests/`，`python3 -m unittest discover -s tests`）：

- **count 只涨不跌、超过容量**：`put` 在缓冲满时推进了读游标，但仍无条件 `count += 1`，
  导致计数随写入单调增长并超过容量。修复：满时覆盖最老元素、计数保持不变，仅在未满时递增。
- **两个消费者拿到同一条消息**：`get` 把读游标推进和 `count -= 1` 放在锁外，
  两个消费者可在同一槽位各读一次。修复：取值、推进游标、递减计数全程持锁，原子完成。
- **缓冲未满却丢消息**：槽位数组比容量多留一格（`capacity + 1`），写游标按 `> capacity` 回绕，
  而读游标错误地按 `>= capacity` 回绕，永远跳过最后一个槽位——写到该槽位的消息读不到，
  还会读到残留旧数据。修复：读游标回绕边界与写游标统一为 `> capacity`。
- **snapshot 顺序与写入顺序不符**：原实现直接截取物理数组前 `count` 个元素，
  未从读游标按逻辑顺序遍历。修复：从 head 起按逻辑顺序导出 `count` 个元素。
