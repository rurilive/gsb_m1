# vecpage

按版本维护的页表，纯标准库，无外部依赖。

## 现状

`vecpage/page.py` 提供一个 `PageTable`：

- `PageTable()`：空表，初始版本号为 0
- `map(page, frame, ver)`：把 page 在 ver 版本上映射到 frame
- `walk(page, ver)`：读出 page 在 ver 版本对应的帧，没有映射返回 None
- `unmap(page)`：取消 page 的映射，返回是否真的取消掉了
- `rollback(ver)`：把页表回滚到 ver 版本，丢掉该版本之后的记录
- `version()`：最近一次写入用到的版本号
- `MappingConflict`：同一页面在同一版本上被映射到不同帧时使用的异常类型

每个页面维护一串按版本号升序的 `(版本, 帧)` 记录，帧为 None 表示从该版本起
取消映射；`unmap` 产生的取消记录打在递增之后的新版本上。内部一把锁保护，
多路写入同时进来不会把表写坏。

## 问题

版本化页表上线后出现翻页错乱：按旧版本翻页翻到新帧、取消映射把历史版本一起
抹掉、回滚后页表项仍是新值、同页同版本的并发写入互相覆盖且不报冲突。

## 实现说明

每个页面在 `_log` 里维护一串按版本号升序的 `(版本, 帧)` 记录，帧为 `None`
表示从该版本起取消映射（墓碑记录）。四个关键口径：

- **回溯取值**：`walk(page, ver)` 在页面记录里找版本号不超过 `ver` 的最后
  一条，返回其中的帧；一条都没有（页面未知，或首个映射比 `ver` 还新）返回
  `None`。命中墓碑记录同样返回 `None`，表示该版本上已取消映射。
- **取消记账**：`unmap` 不删历史，只把全局版本号加一，在新版本上追加一条
  `(新版本, None)` 墓碑。取消只从新版本起生效，历史版本照常回溯；页面当前
  已是未映射状态（无记录或最新一条是墓碑）时返回 `False`。
- **回滚口径**：`rollback(ver)` 逐页丢掉版本号大于 `ver` 的记录，剩下的
  原样保留——页面回到回滚点当时的帧，不向后借用新值；一条都不剩的页面整页
  移除。全局版本号收回到 `min(当前, ver)`。
- **冲突判定**：`map` 时发现同页同版本已有真实帧映射且帧号不同，抛
  `MappingConflict`，表不变；同帧重复映射是幂等空操作。不同版本、或同版本
  落在墓碑上的重映射不算冲突。所有判定与写入都在同一把锁内完成，并发写入
  恰好一路成功、一路报冲突。
