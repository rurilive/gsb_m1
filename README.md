# idemkey

支付链路的幂等键存储：按幂等键记住已处理请求的结果，同一个键再提交时
回放上次的结果，避免重复扣款。纯标准库，无外部依赖。

## 模块说明

`idemkey/store.py` 提供 `IdempotencyStore(ttl=None, clock=time.monotonic,
path=None, max_result_size=None)`：

- `begin(key)`：提交前问这个键要不要干活。返回 `True` 表示该由本次请求
  处理；返回 `False` 表示这个键已经处理过，调用方改用 `get(key)` 回放结果
- `finish(key, result)`：把处理结果记到键上，这个键之后就算已处理，返回
  实际存下的结果（超体积上限时为 `TruncatedResult` 截断标记）
- `get(key)`：取这个键已记下的结果，没有就返回 `None`
- `ttl`：记录存活秒数，**从 `finish` 完成时刻起算**（处理耗时不计入），
  `None` 表示永不过期；长流程在收工时自动获得一轮完整有效期，无需为
  续期重跑
- `clock`：时间读取统一走它，便于测试注入
- `path`：记录落盘的文件路径，`None` 表示只放内存
- `max_result_size`：结果体积上限（JSON 序列化后的 UTF-8 字节数），`None`
  表示不限制；超限时只保存 `TruncatedResult(size, limit)` 截断标记，取回
  方可据此识别结果被截断过，大结果不会撑爆内存与落盘文件
- 键规范化只做首尾空白裁剪，**保留原大小写**：`Order-1` 与 `order-1` 是
  两个独立的键
- `begin` 占键后若一直没有 `finish`（处理失败或进程崩溃留下的残键），
  重发时同一键可以重新开工，不会被永久卡死，也不再出现 `begin=False`
  而 `get=None` 的“空结果”情形

记录字段：`result` 保存结果，`created_at` 是键被占上的时刻，`finished_at`
是收尾时刻（同时是有效期起算点）。内部一把锁保护，磁盘读写也在锁内完成。

## Known Issues

以下问题曾在对账中暴露，均已修复，`tests/test_regressions.py` 锁定修复
后的行为，作为合入前提必须通过。

1. **大小写不同的单号被并成一笔，回放串单导致重复扣款**
   - 现象：`Order-7001` 处理完后，`order-7001` 的提交被判重复并拿回前一
     笔的回执；运营以为没扣成功而补发，用户被多扣。
   - 根因：键规范化使用 `key.strip().lower()`，字母一律折小写，两个本应
     独立的单号被映射到同一个键。
   - 修法：规范化只保留首尾空白裁剪（`strip()`），不再折大小写，大小写
     不同的键严格区分。

2. **服务重启后键还在、结果没了，重发判重复又取不回结果**
   - 现象：处理过的单子半夜重启后 `get` 返回 `None`，但 `begin` 仍返回
     `False`，重发全被判重复卡住。
   - 根因：`begin` 占键后调用了 `_save()` 落盘，而 `finish` 写完结果后没
     有落盘；盘上只剩“键已占、结果为空”的半成品，重启后恰好被读回。
   - 修法：`finish` 写完结果与收尾时刻立即 `_save()`；过期清理删除键后
     同样落盘，重启后可正常回放。

3. **处理中途失败，键永久卡死，重发只回空结果**
   - 现象：下游超时、单子半途失败后，同一键再提交 `begin` 永远返回
     `False`，`get` 永远是 `None`，再也发不出去。
   - 根因：`begin` 先插入 `result=None` 的在途占位记录，失败时没有回滚或
     释放路径；后续 `begin` 只判断“记录是否存在”，占位残键被当成已处理。
   - 修法：`begin` 只把 `finished_at` 非空（真正收尾）的记录判为已处理；
     遇到没写完结果的残键（含重启后从盘上读回的）直接重新占键开工。

4. **长流程单子刚收工就被判过期，离有效期还早却取不回**
   - 现象：处理耗时超过 `ttl` 的单子，`finish` 之后立刻 `get` 返回
     `None`。
   - 根因：过期判断以 `created_at`（占键时刻）为起点，处理耗时也被计入
     有效期，与“ttl 从请求完成时刻起算”的语义不符。
   - 修法：`_purge` 改以 `finished_at` 为起点计算，尚未 `finish` 的在途
     记录不参与过期清理。

5. **有效期无法按完成时刻续期，长流程只能重跑**（功能补全）
   - 现象：长流程单子担心“结果刚写入就过期”，只能中途重跑整笔单来续命。
   - 修法：有效期起点改到 `finish` 时刻后，每笔单收工时自动获得一轮完整
     `ttl`，即按完成时刻续期，处理中途再久都不必重跑。

6. **结果体积超上限撑爆缓存，取回时看不出异常**（功能补全）
   - 现象：超大回执原样写入内存和落盘文件，缓存被撑大，取回方也无法区分
     完整结果与不完整结果。
   - 修法：新增构造参数 `max_result_size`（JSON 序列化后的 UTF-8 字节
     数）；超限结果不落库，替换为 `TruncatedResult(size, limit)` 截断
     标记，标记可正常落盘/盘回，取回方用
     `isinstance(result, TruncatedResult)` 识别。
