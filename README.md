# verkit

依赖管理工具里的语义化版本模块，单进程内嵌，纯标准库，无外部依赖。

## 现状

`verkit/version.py` 提供 `parse_version(text)`（解析 semver 2.0.0 字符串，
非法输入抛 `ValueError`，不接受 v 前缀与前导零）与 `compare(a, b)`
（优先级比较，返回 -1/0/1，接受版本对象或字符串）。prerelease 标识符的
优先级规则（数字低于字母数字、更长的标识符组更高、正式版高于一切预发布）
与 build 元数据忽略规则按规范实现。

## 问题

调用方现在只能拿到两两比较的结果。"这个版本落不落在某个版本区间"的判断
散落在各个调用点，prerelease 该不该参与匹配各写各的，口径不一致，
间接依赖的版本约束（`^` / `~` 那套写法）没法直接消费。

## 约定

- `parse_version` / `compare` 的现有行为不变（`tests/test_version.py` 是行为基线，一个字不改）
- 新能力以新增接口提供，不改动现有函数签名
- 纯标准库

## 运行

```bash
python3 demo.py                          # 解析与排序演示
python3 -m unittest discover -s tests -v # 行为基线测试
```

## 实现说明（区间）

- `verkit/range.py` 新增 `parse_range` / `match` / `best` / `overlaps` / `normalize`，不改动 `version.py` 的任何签名。
- 区间按 `||` 切 OR 分支，分支内空格分隔的比较子取 AND；`1`、`1.2` 缺省补 `.0`，`x`/`*` 为通配。
- `^` 取第一个非零段位进位作上界（`^0.2.3`→`>=0.2.3 <0.3.0`，`^0.0.3`→`>=0.0.3 <0.0.4`）；`~` 只放开 patch（有 minor 时）。
- `!=1.2` 这类部分版本排除展开成 `<1.2.0 || >=1.3.0` 两个分支；`!=1.2.3` 是分支内排除点。
- prerelease 默认不匹配；仅当同一 OR 分支里有比较子对同一个 x.y.z 显式带 prerelease 才放行。
- `normalize` 把每个分支折算成区间 [下界, 上界]，丢弃空分支，合并重叠或相邻（端点相接且至少一侧含端点）的纯区间分支。
- 含 `!=` 或 prerelease 比较子的分支不参与合并、原样保留，因此化简前后 `match` 的结果集完全一致。
- `overlaps` 对两两 OR 分支做区间求交：交集缩成单点时被任一分支的 `!=` 排除才算不相交。
