# cachex

固定容量的键值缓存，纯标准库，无外部依赖。放进去、取出来，满了就把最久没用
的那条挤出去。键与值都是一般对象。

## 现状

cachex/cache.py 提供 Cache：

- Cache(capacity)：按条目数上限构造，容量必须是正整数，否则构造处拒绝
- get(key)：命中返回值并把它记为最近使用，未命中返回 None
- put(key, value)：写入键值，已有键只覆盖值不动次序，新键在满容量时先淘汰
- peek(key)：只取值，不动次序也不记统计
- keys()：全部键，按最久未使用到最近使用排列
- stats()：容量、条目数、命中、未命中与淘汰数
- len() / in：条目数与成员判断

淘汰挑最久未使用的条目，每次淘汰都扫一遍全部条目。

## 问题

淘汰每次都遍历全部条目逐一比较，条目一多就慢，取用与写入也都要重新排一遍；
缓存里只有最久未使用这一种挑法，想按访问频次或按先进先出淘汰都办不到；
容量为一、容量为零、反复取同一个键再淘汰这些边角情形没有明确的淘汰序出口；
也看不到一次操作到底碰了几个节点，摸不清和朴素扫描的差距。
