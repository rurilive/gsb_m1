# shardstore

缓存层的内存键值表，纯标准库，分片集合在建表时定死。

- `shardstore/store.py`：`ShardedKV` 的 `put()` / `get()` / `delete()` 读写，`shard_of()` 查键落在哪片，`keys_in()` / `size()` / `distribution()` / `total()` 看分布
- `tests/test_store.py`：行为基线
- `tests/test_split.py`：在线分裂行为
- `demo.py`：读写与分布演示，附在线分裂演示

## 实现说明

- 路由：建表时的片列表是基线，键仍按哈希取模落基线片；每次分裂占一个独立哈希位（另一份加盐摘要），`shard_of()` 沿已提交的分裂记录按位下钻，未分裂的片路由永不变，可连续再劈。
- 分裂中：目标半区的键读先查新片、未中回老片捞；写与删两片都落，搬走的键不会成孤儿；提交前 `shard_of()` 始终指老片，不会切早。
- 进度：`split_progress()` 报已搬 / 剩余；每批检查点把分裂状态（含已搬键值日志）经临时文件 + `os.replace` 原子写进 `state_path`。
- 断点：重启后用同一 `state_path` 构造，已提交的分裂直接恢复路由，未完成的从检查点接着搬，已搬的键不重搬。
- 切换：搬完才允许提交；先把"已提交"落盘，再一次性换掉路由表并清掉老片里分出的键；崩溃只在落盘前（全退，老片数据完整）或落盘后（恢复同一提交路由），没有半新半旧。
- 回滚：`abort_split()` 随时可调，老片在提交前始终持有全量键，弃掉新片即全退。
