# planopt

纯标准库的内存查询执行与优化雏形，无外部依赖。

## 现状

planopt/table.py 提供一张行式表 Table：

- Table(name, rows, columns=None)：具名表，逐行拷一份，列缺省按行里键的顺序推导
- filter(predicate)、count、columns、to_dicts 都对外只读，改不动原表

planopt/exec.py 提供一个朴素的查询执行器：

- Query(table)：查询构建链，where、select、join、group_by、agg 每步返回新 Query
- 执行是一条写死顺序的流水线：扫描、连接、过滤、投影、聚合按固定次序逐段跑
- 连接用嵌套循环，逐对比较左右两行，过滤条件一律排在连接之后才生效
- 读列时整行读到底，用不上的列也照样搬来搬去
- explain 只给出节点名与子节点的算子树，没有代价，也没有估计基数
- execute(query) 返回结果表与 ExecStats，统计里能看到扫描行数与比较次数

## 问题

现在的执行器是把算子按固定顺序串起来直跑，中间没有任何计划层面的思考。谓词
只能等在连接之后才生效，连接因此先造出一大张中间结果再丢掉大半；投影不到最后
一步不做，未用到的列一路被读进来；多表连接时顺序完全写死，基数小的一侧没有
优先被连；更麻烦的是没法估算代价，选哪条路、省了多少，全靠事后猜。算子还是
一堆按次序调用的函数，没有逻辑计划这层可重写的中间表示。

## 目标

在现有基础上补出逻辑计划、等价重写、代价模型与连接顺序枚举，见任务描述。约束：

- 现有行为与 tests/test_exec.py 基线保持一致（基线一个字不改）
- 纯标准库
- 结果必须与朴素执行逐行对拍一致，优化只该省下工作量，不该改结果
