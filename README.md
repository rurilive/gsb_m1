# paltree

内存里的朴素回文子串工具，纯标准库，无外部依赖。

## 现状

`paltree/tree.py` 提供 `BrutePalTree`，内部存一个字符串，所有回文相关的
事实都当场从枚举子串算出来：

- `text` / `len(t)`：读回当前文本与长度
- `is_pal(s)`：判断某个子串是否回文；不是当前文本的子串就报错
- `palindromic_substrings()`：把所有下标区间过一遍，挑出回文的按起点、
  再由短到长收进列表，同一个回文出现几次收几次，不去重
- `pal_count_by_end(i)`：统计以位置 i 为结尾的回文子串个数
- `contains_pal(x)`：判断某个回文是否作为子串出现
- 异常统一挂在 `PalTreeError` 下：`IllegalArgument`、`NotASubstring`、
  `IndexOutOfRange`

## 问题

每问一件事都要当场枚举：判断回文要从两端往中间比，收集全部回文子串要
把所有区间判一遍，统计某位置为结尾的回文个数要把以它结尾的每个区间都
判一次，判断某个回文是否出现又把整段文本扫一遍。没有任何预处理，文本
一长，平方级的代价就顶不住，反复查询更是白走。

## 目标

在当前基础上，以回文树（回文自动机）为核心把 `BrutePalTree` 扩成能线性
扫描一遍就撑起全部回文统计的字符串结构，补出失配链与长度零、长度负一
两个根、本质不同回文个数、逐位置增量、各回文出现次数、最长与最短回文、
按长度分布、复杂度计数、边界与确定性，见任务描述。约束：

- 现有行为与 `tests/test_tree.py` 基线保持一致（基线一个字不改）
- 新行为另开 `tests/test_eertree.py`，纯标准库
- 枚举子串那套路径保留，两条路对同一批数据给出的事实必须一致

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
