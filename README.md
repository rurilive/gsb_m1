# fracprog

一个纯标准库的最优比率工具箱，无外部依赖。给若干带收益与成本的元素，求选取一部分
使收益之和与成本之和的比值最大，做资源分配、费率优选、性价比排序的脚本里总能碰到，
fracprog 就是干这件事的那一层。

## 现状

- `fracprog/naive.py`：给定若干收益与成本为正整数或整数的元素，求使收益之和与成本
  之和之比最大的选取方案，最直白的做法是把全部选取组合逐个枚举出来，每个组合都按
  累加出的收益与成本算一次比值，再在全部组合里取极值。
- `best_selection`：枚举全部组合取最大比值，结果用精确分数表示，返回比值与选取方案。
- `best_selection_k`：恰好选 k 个元素的最优比率，同样枚举全部组合后只留大小为 k 的。
- `best_selection_with_deps`：元素间有依赖时的最优比率，枚举组合后逐个检查前驱链。
- `is_reachable`：判断某给定比率是否可达，枚举全部组合看有没有一个组合的比值达标。
- `combination_count`、`Tool.enumeration_count`：露出朴素路要过一遍的候选组合规模。
- `fracprog/RatioError`：所有可诊断错误的基类，统一继承本模块的 `Erro`。

## 问题

现在求最优比率只有枚举组合一条路，恰好 k 个与带依赖的选取也走着几乎一样的枚举老
路，判断某比率是否可达更是把组合重来一遍。结果都对，但元素数一上去组合数就指数上
涨，稍大一点就压得跑不动；没有二分答案加可行性判定那条把枚举化成对数级判定的独立
做法，也没有动态规划或贪心在特定结构上直接求最优比率的第二条路，想让两条路互相印
证无从谈起；空集合、单元素、成本为零、收益为零、k 越界这些边界混在各处，没定下统
一的口径；给出的最优方案也没有另一条路径来逐项印证。
