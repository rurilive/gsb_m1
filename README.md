# mcmf

最小费用流小库，纯标准库，无外部依赖。

## 现状

`mcmf/flow.py` 提供 `MinCostFlow`，只实现了最朴素的最大流：

- `add_edge(u, v, cap, cost)`：加一条有向边，容量非负整数，费用可为负整数，允许平行边
- `max_flow(s, t)`：在残量网络里反复广度优先找一条增广路，按路上最小剩余容量整条推走，直到无路可增，返回最大流值
- `flow_value()` / `flow_cost()`：当前流量与沿途累加的费用
- `edge_flows()` / `nodes()`：原始边的流量分解与节点清单

参数非法抛 `BadEdge`，所有异常都继承 `Erro`。

## 问题

增广时完全不看单位费用，只按搜索到的先后随便挑路，流量虽然推满了，
路径组合却很随意，总费用通常不是最小。规模一大重复广搜也慢。
