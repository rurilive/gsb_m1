# wildcard

一个纯标准库的小工具: 判断一段文本是否被一个含通配符的模式完全匹配, 并给出
每个星号在匹配中实际吃掉的字符个数。

## 现状

`NaiveWildcard` 用最直白的递归回溯完成判定。模式里问号匹配恰好一个任意字符,
星号匹配任意长度的字符序列; 遇到星号就把零个、一个、两个直到多个字符逐个递归
展开, 一旦整体失败就退回上一个星号再多试一个字符。整个判定没有任何缓存, 也不
做任何剪枝。

## 问题

决定匹配是否成立的是星号, 而每个星号都要从零开始试到文本结束, 同一个子问题被
反反复复展开。星号一多, 展开层数随星号个数指数级增长, 文本稍长就慢得没法接受。
星号吃掉的长度目前靠逐段取最早出现的位置算出, 口径虽确定, 但最坏也要把文本
反复扫描多遍。

## 目标

把判定从指数级递归回溯升级为多项式代价: 用二维状态表逐格填出能否匹配, 或用
最近星号位置配合回退的两指针单趟扫描; 并在此基础上稳定地给出每个星号吃掉的
字符数。原有的递归回溯作为独立做法保留, 两条路对同一批固定输入给出的事实必须
逐项一致, 覆盖空模式、空文本、全星号、连续星号、模式无星号、星号在首尾、文本
为空而模式非空等边界。详见需求描述。

```
python3 demo.py
python3 -m unittest discover -s tests
```
