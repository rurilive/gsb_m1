# beatsx

一个纯标准库的区间取最值与区间求和结构雏形，无外部依赖。

## 现状

`beatsx/seg.py` 只提供朴素实现 `NaiveSeg`，内部是一个整数数组：

- `NaiveSeg(data)`：拷贝一批整数构造，元素必须都是整数
- `get(i)`：取下标处的值，越界报错
- `range_sum(l, r)`：逐项求和半开区间 `[l, r)`，空区间返回 0
- `range_max(l, r)` / `range_min(l, r)`：逐项取最大 / 取最小，空区间返回 `None`
- `chmin(l, r, x)` / `chmax(l, r, x)`：把区间内每个元素逐项改写为与 `x` 的较小 / 较大值
- `to_list()` / `n`：查看当前数组副本与元素个数
- 非法区间一律抛 `BeatsError`，它是本包的异常基类

## 问题

现在所有区间操作都是逐项处理：一次区间取最值要把区间内每个元素都看一遍并改写，
一次区间求和也要把区间内每个元素都加一遍，代价与区间长度成正比。
一个点被反复覆盖之后，原先算过的中间结果一点也留不下来，每次都得从头再算。

## 目标

在保持上述基线行为不变的前提下，补出一套以线段树加区间取最值剪枝为核心的区间结构：
维护区间最大值与次大值、最小值与次小值，只在标记会真正改变元素时才下推，
让区间取最值与区间求和做到均摊对数级，并暴露可读的剪枝与下推计数；
同时支持区间加与取最值的混合、区间最大 / 最小查询、区间最大值首次出现位置等能力。
详见任务描述。约束：

- 现有行为与 `tests/test_seg.py` 基线保持一致（基线一个字不改，且必须全绿）
- 新行为另开 `tests/test_beats.py`，用固定序列与逐字断言
- 纯标准库，Python 3.10+
- 新异常统一继承 `BeatsError` 基类，非法区间 fail fast
- 基线那套逐项路径不许删除，两条路对同一批数据给出的事实必须对得上

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
