# hitcount

空间受限的重频统计小库，纯标准库，无外部依赖。调用方喂进一串元素，
想知道哪些元素出现得最频繁、频次大概多少、误差有多大，而内存不能
随元素种类数无限涨。

## 现状

- `hitcount/naive.py`：`NaiveCounter`，一套全量精确计数。`add(key,
  count=1)` 给元素累加计数，`estimate(key)` 取精确计数（没见过为零），
  `total()` 取累计总量，`distinct()` 取不同元素个数，`top_k(k)` 按
  频次降序给出前 k 个（同频按字典序升序），`reset()` 回到初态。

计数存在字典里，每个不同的元素占一个键，谁也不淘汰。计数是精确的，
但元素种类一多内存就无界；没有有界结构、没有误差口径、拿不出重频
查询的上界，也不能合并，更没有时间窗口。

## 问题

全量字典在元素基数大时内存随种类数无界增长，装不下也扛不住；只有
精确查询，没有估计与误差上界；偶发元素和真实重频一视同仁，没有按
规则驱逐与记账；两个结构不能合并；没有时间窗口，老样本永不淘汰。
