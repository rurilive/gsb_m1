# snapstore

多键一致性快照存储：跨键原子提交，快照读永远对应某一提交时刻，写时复制让快照
不随底层写入漂移，纯标准库，无外部依赖。

## 现状

改造前只有逐键 KV，snapstore/kv.py 提供 KeyValueStore：

- KeyValueStore()：一个键到值的普通字典，所有读写在一把可重入锁下进行
- put(key, value)：写入一个键，键已存在则覆盖
- get(key)：返回键当前的值，键不存在返回 None
- delete(key)：删除一个键，返回该键删除前是否存在
- keys()：当前存在的键，按升序
- __contains__(key)：键是否当前存在
- 键与键之间没有任何一致性关系，写入即生效，取出的值与原对象同一

## 问题

逐键读写撑不起需要跨键一致的场景：一组相关写入没有原子性，中途失败会留下
半提交状态；没有一致读视图，读一组键时可能读到别人改了一半的中间态；
快照若靠整库拷贝，内存随快照数量线性增长；也没有写写冲突的裁决。
