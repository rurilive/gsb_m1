# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下四个线上缺陷已修复（防回归测试见 `tests/`，运行 `python3 -m unittest discover -s tests`）：

- **负数幂符号反转**（`-2^2` 算出 4，应为 -4）：一元负号原先在 `_atom` 层解析，优先级高于乘方，`-2^2` 被解析为 `(-2)^2`。修复：把一元负号提升到独立的 `_unary` 层，置于乘方之下，`-2^2` 解析为 `-(2^2)`；乘方右操作数仍允许负号（`2^-3` 合法）。
- **`and`/`or` 不短路**（`x != 0 and 10 / x > 2` 在 x=0 时抛 ZeroDivisionError）：求值器原先无条件先算左右两支再合并结果。修复：左侧已能定值时直接返回，右侧分支不再求值，结果仍为布尔值。
- **负数 `//` / `%` 符号错误**（`-7 % 2` 算出 -1，应为 1）：原先实现用 `int(left / right)` 向零截断，不是向下取整。修复：直接委托 Python 的 `//` 与 `%`，保证向下取整、余数与除数同号。
- **`let` 绑定泄漏**（`let x = 99 in ...` 之后外层及后续规则的 x 被污染）：`_eval_let` 原先直接改写求值器的共享绑定表且不恢复。修复：进入 body 前保存外层同名绑定，退出（含异常）时恢复；外层没有同名绑定时则彻底删除，多次 evaluate 之间互不泄漏。
