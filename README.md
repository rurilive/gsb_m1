# diff3x

配置/文本三方合并（diff3），纯标准库。输入输出都是完整文本，典型用途是把
各环境对同一份基线配置的改动合回主线。

## 语义约定（以下为本模块的正式行为定义）

1. **输入与切分**：`merge(base, a, b)` 三个参数均为完整文本（str），按 `'\n'` 切分为行，行内不含 `'\n'`；以换行结尾的文本切分后末位是空串，拼接时还原。
2. **换行处理**：行比较前剥离行尾 `'\r'`，CRLF 行与 LF 行视为同一行，**仅 `'\r'` 差异不构成改动**；输出保留来源行的原始内容（含 `'\r'`）。
3. **改动区域**：以 base 的行坐标为基准，每侧相对 base 的改动表现为若干替换区域（含插入与删除）。
4. **合并规则**：仅一方改动的区域取该方内容；双方均未改动的区域取 base。
5. **冲突判定**：双方改动区域在 base 坐标上相交时——
   - **双方替换内容完全相同 → 干净合并，只保留一份**；
   - **一方删除（替换为空）、另一方修改 → 冲突，任何一侧都不得被静默丢弃**；
   - 其余情况 → 冲突。
6. **冲突块边界**：**冲突块只覆盖双方改动基区的并集，紧邻的未改动行不得并入冲突块**。
7. **结果结构**：返回 `MergeResult`——
   - `lines`：list[str]，干净区域按序拼接；冲突处插入标记块，依次为 `<<<<<<< a`、a 侧行、`||||||| base`、base 侧行、`=======`、b 侧行、`>>>>>>> b`，七个标记行顶格；
   - `conflicts`：list[Conflict]，每个含 `base_lines` / `a_lines` / `b_lines` 与 `base_span` / `a_span` / `b_span`；**span 为 0 起始、含头不含尾的 (start, end) 行区间**，对应该侧在冲突块中的行范围；
   - `clean`：conflicts 为空即 True。

## 运行

```bash
python3 demo.py
```

## 测试报告

测试位于 `tests/test_diff3.py`，纯标准库 `unittest`，可三种方式独立重复
运行（`python3 -m unittest tests.test_diff3`、`python3 tests/test_diff3.py`、
`python3 -m unittest discover -s tests`），随机用例全部使用固定 seed，
不依赖时序。当前结果：**38 个用例，17 绿 / 21 红**（红用例为有意保留，
每个红用例上方注释均写明「README 期望 / 实际发生」）。

红用例钉出 8 类源码与 README 的出入：

1. **相同替换被误报冲突**（`merge()` 中 `arep is brep` 身份比较）：README §5
   要求双方替换内容相同即干净合并保留一份，实际两侧 list 身份恒不等，相同
   改动被报冲突并展示两遍。修复方向：改为值相等比较（归一化后 `==`）。
2. **删除方被静默丢弃**（`if not brep: take_clean(arep)` 两个分支）：README §5
   要求「一方删除、另一方修改」必须冲突，实际直接采用修改侧、删除无痕消失。
   修复方向：删除仅在两侧内容一致时干净合并，否则进入冲突分支。
3. **冲突块多吞一行未改动行**（冲突分支无条件 `hi += 1`）：违反 README §6，
   `base_lines`/`base_span`/`lines` 三处一并越界，无末尾换行时 span 还会超出
   实际行数。修复方向：删除自增，基区严格用并集 `[lo, hi)`。
4. **侧行未做 `\r` 归一化**（`_side_edits` 只对 base 调 `_canon`）：违反
   README §2，CRLF 与 LF 行被当成不同行，三方全 CRLF 都能误报冲突，单侧仅
   `\r` 差异时还会错取侧行原文而非 base。修复方向：对两侧行同样应用
   `_canon` 再比较，输出仍取原始行。
5. **同点零长度插入不归组**：README §5 要求双方在同一位置的相同插入合并为
   一份，实际相交判定只覆盖正长度区间，相同插入被静默输出两份。修复方向：
   两侧同一基坐标的零长度插入视为同区域。
6. **插入点落在改动区间边界时漏并**（分组循环条件 `base_start < hi`）：一侧
   的插入点等于另一侧改动区间端点（点在 `[lo, hi)` 内）时本应冲突，实际整
   组被漏掉、两侧改动静默错合并产生重复行。修复方向：用完整的区间/点相交
   谓词（含 `lo <= point < hi`）驱动归组。
7. **链状相交冲突块漏掉侧内对齐的未改行**：经相交链（a 改 `[1,3)`、b 改
   `[2,5)`、a 再改 `[4,6)`）合成的冲突块里，a 侧片段只拼接各替换区 repl，
   漏掉块内未改动的对齐行，与 README §7 给出的 `a_span` 切片不自洽。修复
   方向：侧片段按该侧在块内的最小/最大行坐标区间整体切片。
8. **对拍总体验证**：文件内含按 README 直译的朴素参考实现（手写 LCS 逐行
   对齐、双方均做 `\r` 归一化），固定 seed 下与源码对拍 7500 例（纯 LF
   4000、CRLF 混合 2000、末尾无换行/空文件/末换行形态不一致 1500），当前
   三阶段均有分歧，分歧均可由上述 1–7 解释（修复版与参考实现对拍 16000+
   例零分歧）。修复方向：按 1–7 修复后三个对拍用例应转绿。

`python3 demo.py` 在当前源码上照常运行（演示用例两侧改动不相交，恰好为
干净合并），测试未改动 `diff3x/` 任何源码与 `demo.py`。
