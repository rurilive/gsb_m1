# connpool

进程内连接池，纯标准库，无外部依赖。应用要反复拿数据库连接干活，
每次都新建代价太大，connpool 就是管这层借还的那一层。

## 现状

connpool/pool.py 提供固定上限的连接池 ConnectionPool：

- ConnectionPool(max_size, factory=None, clock=time.monotonic)：max_size 为连接数目上限，factory 可选自定义建造，clock 为注入时钟
- acquire()：借出一条连接，池里有空闲就复用，没有空闲且未达上限就新建，达到上限就阻塞等待归还
- release(conn)：归还借出的连接，唤醒等待者；归还不是本池借出的连接抛 ValueError
- stats()：返回 active / idle / created 计数快照
- Connection：带 cid、created_at、is_healthy()、mark_unhealthy()、close()
- 内部一把锁加条件变量保护，多线程借还安全

现有实现只有一次借一个、用完归还这一条路：借出没有时限，池满时调用方被无限期
挂住；连接用久了可能失效，池照旧把坏连接借出去；空闲连接只增不回收；借出的连接
没有事务概念，一次事务里的多条操作可能落到不同连接上；借出多久没还、有没有泄漏，
都无处查询；也没有关闭语义，下线时在借的连接无从处置。

## 问题

把现有这套朴素的借还扩成生产可用的连接池，缺的东西集中在几处：没有等待队列，
池满只能干等且等不到头；没有时限，调用方无法自己掌握超时；没有溢出通道，池满时
想临时多借一条都做不到；借出前不探活，坏连接直接交给调用方；空闲连接不回收；
事务里的操作绑不到同一条连接，事务没结束连接就可能被还回池里；借出超时未归还的
连接没有标记与报告；统计里也看不出等待者与溢出的情况。
