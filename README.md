# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下四个问题均已修复，`tests/` 下有对应的防回归用例。

1. **`-2^2` 被算成 4**
   根因：递归下降语法分析里一元负号在“原子（atom）”层解析，优先级反而高于乘方，
   `-2^2` 被归约成 `(-2)^2`。修复：新增独立的一元运算层，优先级位于乘除与乘方之间，
   `-2^2` 正确归约为 `-(2^2) == -4`；乘方右操作数仍允许一元负号，`2^-3` 合法。

2. **`x != 0 and 10 / x > 2` 在 x=0 时抛 `ZeroDivisionError`**
   根因：求值器对 `and`/`or` 先无差别地求值左右两支，再交给 Python 的 `and`/`or`，
   短路只发生在值已算出之后，右支的除零无法避免。修复：求值器先算左支，左支已能定值
   （假 for `and`、真 for `or`）时直接返回布尔值、不求值右支；结果仍统一为 `bool`。

3. **`-7 % 2` 得 -1、`-7 // 2` 得 -3**
   根因：`//` 与 `%` 是用 `int(left / right)`（向零截断）实现的，只在同号时与向下取整
   巧合一致，异号时整组偏差一个符号。修复：直接采用 Python 原生的 `//`（地板除）与 `%`
   （余数符号跟随除数），并满足恒等式 `a == (a // b) * b + a % b`：
   `-7 // 2 == -4`、`-7 % 2 == 1`。

4. **`let x = 99 in ...` 污染外层及后续 evaluate**
   根因：求值器只有一张挂在实例上的扁平绑定表，`let` 直接写表、退出时不恢复，
   `variables` 入参也被原地 `update` 进去，导致内层绑定穿透到外层并泄漏到后续调用。
   修复：绑定改为作用域栈——每次 `evaluate` 压入独立作用域（结束即弹出），
   每个 `let` 为 body 压入新作用域（在外层求完绑定值后入栈），变量沿栈向外查找；
   调用方传入的 `variables` 字典不再被修改。
