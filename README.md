# segtre

纯标准库的区间求和雏形，无外部依赖。

## 现状

segtre/array.py 提供一个 SegArray：

- 初始化：用一串整数建起来，bool 不算整数，非整数报 ValueError
- 下标访问与 to_list：按下标取回单个元素，to_list 返回底层数据的一份副本
- range_sum：唯一的区间入口，半开区间 [left, right)，空区间返回 0，
  这一步把区间里的元素挨个拿出来累加，看过几个元素就是几个元素的代价
- set_value、add_value：把下标处直接改成某个值、直接加上某个增量，返回旧值
  或新值，越界报 IndexError
- last_cost：上一次 range_sum 看过的元素个数，用来观察代价

查询只有逐元素累加这一条路，区间一长就要把区间里每个元素都摸一遍，值变更
也只是就地改一个格子；没有建树，没有区间最值，没有点更新与区间更新的区分，
没有懒惰传播，也没有可配置的合并函数与按前缀二分的定位。

## 问题

每次区间查询的代价和区间宽度成正比，整段查询就等于把整串数据重扫一遍，查询
一多就白扫；想要区间最值只能自己遍历区间去比；区间加与区间赋值这类成片改动
只能一个下标一个下标地改，改一长段就要赋一长串值，中间过程也留不下任何可以
复用的聚合；改完之后其它区间的查询还是要从头再算，没有把已经算好的结果缓存
在节点里的结构；聚合方式写死了求和，想换个最小或最大的口径就得改代码；想找
前缀和第一次达到某个目标的位置，也只能从头累加着试；边界与非法合并函数的
处理也没有明确口径。

## 目标

在当前基础上补出线段树、懒惰传播与多种聚合，见任务描述。约束：

- 现有行为与 tests/test_array.py 基线保持一致（基线一个字不改）
- 纯标准库
- 区间查询、点更新、区间更新之后的结果必须与朴素逐元素求和逐项对拍一致，
  线段树与懒惰传播只该换掉算的路径，不该改结果
