# binanswer

一个只用 Python 标准库的最优化可行性工具包。包内模块 binanswer.py 提供
BinaryAnswerKit 类，围绕"把答案限制在可能取值里逐个试可行"做八件事：
minimize_max_segment_sum 求把序列顺序切成不超过 k 段时各段和最大值的最小
可能值，maximize_min_segment_sum 求恰好切成 k 段时各段和最小值的最大可能
值，min_eating_speed 求满足某单调条件的最小整数，min_max_pair_gap 求序列
上先切一刀再在段内取相邻元素的最小最大差值，segment_plan 给出取得最优时的
划分点，feasible 单独暴露可行性判定，candidate_bounds 与 sweep_bound 走
候选取值枚举。

## 现状

八件事一律靠朴素做法：求解先定出答案可能取到的整数区间，再从最小值起逐个
整数往上试可行性，第一次可行即为答案；可行性判定本身线性扫一遍序列累加，
超过上限就切段。min_max_pair_gap 则枚举每一处切分，再枚举段内全部元素对取
最小差。划分方案在多个并列时逐点比对取字典序最小，可行判定与候选枚举各扫
一遍。规模小时直观可靠，结果一眼能看穿。

## 问题

朴素做法在值域一大就退化：逐个整数往上试，试的次数正比于答案区间宽度乘上
线性判定的数据量，值域放大一点点数就涨得飞快。实现既没有把试答案的次数压
下来的手段，也没有任何计数能说明二分答案到底省了多少，更与逐个试的事实无
从对照，两条路之间没有任何核验。调用方拿到一个结果，既不知道它试了多少次，
也无法判断换一条更快的路会不会悄悄改了结论。

## 目标

把 BinaryAnswerKit 从逐个试答案扩成一套二分答案工具集：对答案所在的单调区
间做二分，每次用线性可行性判定把区间收窄一半，把值域那一重从线性降到对数，
四项能力——分段最小化最大段和、最大化最小段和、满足单调条件的最小整数、序
列上最小最大差值——都改走二分；再另起一条动态规划或贪心判定加逐个试的独立
做法，与二分路互不调用，两条路对同一批数据逐项一致；可行性判定与划分方案各
接一个独立能力并与整体求解口径一致；暴露逐个试答案次数与二分判定次数的规模
差距，值域放大时显著分层；覆盖空序列、单元素、答案为负、答案为零、全部元素
相同、段数大于元素数、段数为一、序列含负数、非法输入等边界；固定输入重复跑
结果一致且不依赖模块级可变状态；异常统一继承 BinErro 基类并快速失败；基线那
条朴素路径一条都不许删。
