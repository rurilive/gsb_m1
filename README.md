# geolib

二维矩形索引工具包，纯标准库，无外部依赖。

## 现状

`geolib/spatial.py` 提供一个朴素矩形索引 `FlatIndex`：

- `insert(rect, name)`：追加一条矩形，`rect` 是四元组左下右上坐标，`name` 是标识
- `contains_point(x, y)`：线性扫描，返回包含该点的全部标识，按插入顺序
- `intersect(rect)`：线性扫描，返回与给定矩形相交的全部标识，按插入顺序，边界接触算相交
- `nearest(x, y)`：线性扫描，返回距离点最近的标识，距离是点到矩形的曼哈顿距离，
  平局返回插入顺序靠前者，空索引返回 `None`
- `remove(name)` / `names()` / `items()` / `count()`：按标识移除、按插入顺序列出标识与矩形
- 坐标非法（左下角大于右上角）时抛 `RectError`，它是 `GeoError` 的子类

## 问题

一个矩形列表扛下全部查询，任何点查询、相交查询、最近邻都要把整张列表走一遍。
矩形一多，一次查询里绝大多数的判断都是白扫，规模上去以后完全撑不住。

## 目标

把 `FlatIndex` 从线性扫描扩成以空间划分树为核心的二维空间索引：

- 按轴交替或最小包围盒划分构建树，点查询与相交查询平均做到对数级
- 与暴力逐项结果一致，最小包围盒随插入删除正确维护
- 最近邻、范围计数、复杂度计数、边界情形、确定性全部补齐，详见任务描述

约束：

- 现有行为与 `tests/test_spatial.py` 基线保持一致（基线一个字不改）
- 纯标准库，Python 3.10+
- 不许把查询做成换皮的全表扫描，必须能给出访问节点数明显小于矩形数的证据

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
