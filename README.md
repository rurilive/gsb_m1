# lrucache

进程内固定容量缓存，纯标准库，无外部依赖。应用要用少量内存装下热点数据，
lrucache 就是管这层淘汰的那一层。

## 现状

lrucache/cache.py 提供最朴素的 LruCache：

- LruCache(capacity)：capacity 为容量上限，正整数
- get(key)：取值，命中返回该值并记为一次使用，未命中返回 None
- put(key, value)：写入，键已存在则更新值并记为一次使用
- keys() / snapshot()：按插入顺序的键清单与内容浅拷贝
- evictions()：累计淘汰次数
- 淘汰只在容量满时发生，线性重扫全部条目的访问时间戳，取最旧者删除
- 容量非法抛 CacheError，所有异常都继承 Erro

现有实现只有最近最少使用这一种口径：每次淘汰都要把全部条目重新扫一遍，
条目一多淘汰就慢；没有过期时间概念，写入的条目只能靠容量被动挤走；
也没有按使用频率的淘汰口径；命中率、每次淘汰了哪个键、末态内容这些
事实只留在调用方手里，无法与另一条独立口径互相印证。

## 问题

把现有这套朴素的淘汰扩成生产可用的缓存策略，缺的东西集中在几处：淘汰
是线性扫描，规模一大就退化；没有存活时间，过期条目要等淘汰才走；没有
使用频率口径，热点与否区分不开；没有稳定可复读的命中率与淘汰轨迹，改完
也无从对照新老结果是否一致。
